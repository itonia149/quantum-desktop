# Quantum Desktop

Open your local files in a real browser interface using [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser). This independent Linux desktop integration adds a launcher, local user service, Arch packaging, and migration support. It is not a fork of Quantum.

## Arch Linux installation

```sh
yay -S quantum-desktop
quantum-desktop-setup --folder "$HOME/Documents" --folder "$HOME/Downloads"
quantum-desktop
```

Launch **Local Files (Quantum)** from the application menu, or open http://127.0.0.1:8085/ after starting the service. New setups use read-only sources. Add `--writable` when creating a new setup to enable file management. Use `--folder "$HOME"` to expose your home directory, or `--folder /` for filesystem-wide browsing subject to normal account permissions. Large sources can require significant indexing time.

Dependencies: Linux x86_64, Python, systemd, and Microsoft Edge Stable. `--browser chromium` or another Chromium-based executable can change the browser used by setup. The AUR package depends on Edge Stable for its default configuration.

## Adopt an existing setup

```sh
quantum-desktop-setup --adopt-config /path/to/existing/config.yaml
```

The migration accepts **JSON-formatted YAML**, as generated by this integration. General YAML must first be converted to JSON. It requires an absolute database path and an existing `server.listen: 127.0.0.1` setting. Sources, permissions, database, and port are preserved. Run setup as the normal desktop user, not root.

The service stops briefly while setup backs up its database and configuration. Previous files are saved under `~/.local/state/filebrowser-quantum/package-migration-TIMESTAMP/`. The old user desktop entry is removed after backup so the package's entry takes effect. Source folders and their files are not moved or copied.

## Behavior and access

Quantum offers folder browsing, search, previews, and file-management actions where enabled. Browser agents can inspect filenames, controls, and rendered Markdown previews. Native previews do not provide our PDF reader's page-context contract or SilverBullet's math and wikilink workflow. Integrations with those applications are not included.

The service listens on localhost only, with no login. Other processes and users on the computer can access exposed files. With writable sources, changes and deletions affect original files. The process runs with normal user permissions, not root. WebDAV is disabled in new setups. Existing configurations retain their settings.

The launcher starts the service on demand. It stays running until stopped or logout; setup does not enable login startup.

```sh
systemctl --user status filebrowser-quantum
systemctl --user stop filebrowser-quantum
systemctl --user start filebrowser-quantum
journalctl --user -u filebrowser-quantum -n 30
yay -Syu
```

## Installed files

| Path | Purpose |
| --- | --- |
| `/usr/bin/quantum-desktop` | Browser launcher |
| `/usr/bin/quantum-desktop-setup` | Setup and migration |
| `/usr/lib/quantum-desktop/filebrowser` | Pinned upstream server |
| `/usr/share/applications/filebrowser-quantum-local.desktop` | Menu shortcut |
| `~/.config/quantum-desktop/` | Private server and launcher configuration |
| `~/.config/systemd/user/filebrowser-quantum.service` | User service |
| `~/.local/share/filebrowser-quantum/` | Default database and cache |

The package pins Quantum v1.5.6-stable and verifies the official binary's SHA-256 checksum. Upstream updates arrive through package updates. User configuration is not replaced during package upgrades.

To uninstall, stop the service, remove the package with `sudo pacman -R quantum-desktop`, remove the user service, and run `systemctl --user daemon-reload`. Keep configuration and database if you want to reinstall. Your exposed folders are separate and must not be deleted.
